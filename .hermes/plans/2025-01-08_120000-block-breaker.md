# Block Breaker (DX-Ball style) — Implementation Plan

## Goal
Replace the placeholder `src/main.ts` and `src/style.css` with a fully playable
DX-Ball-style block breaker game using Three.js, following all AGENTS.md rules.

---

## Game Overview

- Paddle at the bottom, controlled by mouse / touch drag / arrow keys
- Ball bounces around the arena, destroying blocks on contact
- Blocks arranged in a grid at the top — multiple rows, multiple colors (representing hit points)
- Ball lost when it falls below the paddle → lose a life
- Clear all blocks → advance to next level (faster ball, more rows)
- Power-ups drop from some blocks and fall to the paddle

---

## Architecture

Single class: `BlockBreakerGame` inside `src/main.ts`.

### GAME_CONFIG (all tunable values)

```
ARENA_WIDTH, ARENA_HEIGHT, ARENA_DEPTH
PADDLE_WIDTH, PADDLE_HEIGHT, PADDLE_SPEED
BALL_RADIUS, BALL_INITIAL_SPEED, BALL_SPEED_INCREMENT (per level)
BLOCK_ROWS, BLOCK_COLS, BLOCK_WIDTH, BLOCK_HEIGHT, BLOCK_PADDING
BLOCK_HIT_POINTS (per color tier: 1, 2, 3)
LIVES_START
POWERUP_DROP_CHANCE (0.0–1.0)
POWERUP_FALL_SPEED
LEVEL_SPEED_MULTIPLIER
```

### State enum pattern (no TS enum — use const object)

```ts
const GamePhase = { MENU: 'MENU', PLAYING: 'PLAYING', GAME_OVER: 'GAME_OVER', LEVEL_CLEAR: 'LEVEL_CLEAR' } as const
type GamePhase = typeof GamePhase[keyof typeof GamePhase]
```

### Interfaces

```ts
interface Block   { mesh: THREE.Mesh; box: THREE.Box3; hp: number; row: number; col: number }
interface Ball    { mesh: THREE.Mesh; box: THREE.Box3; velocity: THREE.Vector3 }
interface Paddle  { mesh: THREE.Mesh; box: THREE.Box3 }
interface PowerUp { mesh: THREE.Mesh; box: THREE.Box3; type: PowerUpType }
```

## Scene Setup

- Orthographic or perspective camera — perspective, top-angled (like DX-Ball 3D)
  or fully top-down 2.5D. Recommend: perspective camera looking slightly down the
  Z axis so it feels 3D but plays like 2D.
- Directional light + ambient light. Shadows optional (blocks look great with
  MeshStandardMaterial + subtle shadows).
- Arena walls: invisible Box3 boundaries (left, right, top) — no visible mesh needed,
  or thin wall meshes for aesthetics.
- Background: dark color or subtle gradient via CSS on the canvas container.

## Step-by-Step Implementation

### Step 1 — Scaffold & scene
- Clear `src/main.ts` of placeholder content
- Set up renderer, camera, scene, lights, clock
- Render loop with capped delta
- Resize handler

### Step 2 — Paddle
- BoxGeometry paddle mesh, centered at bottom of arena
- Input: mousemove → map X to paddle position (clamp to arena edges)
- Input: ArrowLeft / ArrowRight keys → move paddle at PADDLE_SPEED
- Input: touch drag → same as mouse
- Box3 updated every frame

### Step 3 — Ball
- SphereGeometry (or BoxGeometry for a classic blocky look)
- Spawns above paddle, launches on Space / tap
- Velocity vector — normalize to BALL_INITIAL_SPEED
- Wall collisions: flip vx (left/right walls), flip vy (top wall)
- Paddle collision: reflect vy, nudge vx based on where ball hits paddle
  (left edge → angle left, right edge → angle right — classic DX-Ball feel)
- Falls below paddle → lose life, respawn ball on paddle

### Step 4 — Block grid
- `buildLevel(level: number)` — generates BLOCK_ROWS + level rows of BLOCK_COLS blocks
- Color tiers by HP: green (1 hit), yellow (2 hits), red (3 hits)
- Each block: BoxGeometry + MeshStandardMaterial with color per HP tier
- Stored in `this.blocks: Block[]` array

### Step 5 — Ball–Block collision
- Each frame: iterate `this.blocks`, check `ball.box.intersectsBox(block.box)`
- On hit: decrement block HP, update color or remove mesh + dispose geometry/material
- Reflect ball velocity — determine which face was hit (compare overlap on each axis)
  to decide whether to flip vx or vy
- If all blocks cleared → phase = LEVEL_CLEAR → brief pause → next level

### Step 6 — Lives, score, HUD
- HUD via DOM overlay (`insertAdjacentHTML` — never `innerHTML +=`)
- Show: Score | Level | Lives (as icons or text)
- Score: +10 per block destroyed, +HP bonus for multi-hit blocks
- Level complete: brief "LEVEL X CLEAR" message, then build next level

### Step 7 — Power-ups
- On block destroy: Math.random() < POWERUP_DROP_CHANCE → spawn PowerUp at block position
- PowerUp types:
  - WIDE_PADDLE — paddle grows for 10 seconds
  - MULTI_BALL — spawns 2 extra balls
  - FAST_BALL — increases speed temporarily
  - SLOW_BALL — decreases speed temporarily
- PowerUps fall at POWERUP_FALL_SPEED each frame
- Paddle collision → apply effect, remove PowerUp mesh
- Falls below arena → remove and dispose

### Step 8 — Game Over & Menu screens
- MENU phase: overlay with title + "Click or press Space to start"
- GAME_OVER: overlay with final score + restart button
- LEVEL_CLEAR: brief overlay, auto-advances after 2 seconds
- All overlays via DOM divs, not Three.js sprites

### Step 9 — Mobile controls
- Paddle follows touch X position (touchmove on canvas)
- Touch the screen to launch ball
- CSS: show mobile hint text; hide on hover:hover + pointer:fine
- Prevent pinch zoom (viewport meta) + canvas touch-action: none

### Step 10 — Polish
- Ball trail or glow (optional: additive blending on a small sphere behind ball)
- Block destroy animation: quick scale-down tween in the update loop (no lib needed)
- Screen shake on life lost (offset camera position briefly)
- Sound: Web Audio API beep on ball hit, block destroy, life lost (optional)

## Collision Notes

Ball-block overlap reflection algorithm (no physics engine needed):

```
dx_overlap = min(ball.max.x - block.min.x, block.max.x - ball.min.x)
dy_overlap = min(ball.max.y - block.min.y, block.max.y - ball.min.y)
if dx_overlap < dy_overlap → flip vx (hit left/right face)
else → flip vy (hit top/bottom face)
```

## Risks & Tradeoffs

- Multi-ball power-up adds complexity (iterate array of balls, handle all collisions)
  → implement as an array from the start even with 1 ball to make this easy
- Ball tunneling at high speed: if BALL_SPEED * delta > block size, ball skips through.
  Mitigate by capping delta (already in AGENTS.md) and keeping BALL_SPEED reasonable.
  If needed: sub-step the ball movement (split delta into N smaller steps).
- Camera angle: perspective adds depth but slightly complicates 2D collision math.
  Keep all physics in XY plane; Z is cosmetic only.
